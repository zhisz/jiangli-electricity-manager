# 江理电费管家 Android App

原生 Android 应用，每个整点查询江西理工大学南昌校区校付宝房间余额，低于阈值时发送本地通知。在线充值只负责创建校付宝订单并打开官方收银台，支付密码始终由校付宝和微信处理；付款结果由校付宝官方订单接口确认。

本项目由 zhiSZ 开发，采用 [MIT License](LICENSE) 开源。问题反馈：
`3357627169@qq.com`。

## 0.20.0 修改内容

- 从校付宝收银台 URL 的 `tran_no` 提取官方 `payNo`，返回 App 后先按该号码精确查找缴电费记录，再使用记录中的 `orderNo` 查询官方订单详情。
- 只有官方详情明确返回 `payStatus=2` 才自动写入充值记录；不再读取充值前余额，也不再以充值前后余额差额推测付款结果。

- 自动充值记录使用官方 `payTime`，同一天多次充值可按实际付款时间参与趋势修正；成功后额外刷新余额只用于更新页面和图表，不影响官方成功结论。

- 新增支付单号提取、精确列表匹配、官方成功/等待/失败状态，以及房间、金额和单号不匹配拒绝等单元测试。

- 只有金额余额上涨接近用户输入金额时才视为“检测到匹配上涨”，并自动把用户输入的完整金额写入充值记录；普通余额波动不会被误判。由于官方未提供可信的订单结果查询，本功能不会把“从微信返回”本身冒充支付成功。

- 支付期间 App 被系统回收后，再次进入对应房间可恢复最近 30 分钟内的 pending 检测；不保存订单号、收银台 URL、令牌或微信身份。
- 检测按绝对时间跳过慢网下已经错过的轮询点，避免连续补跑拖成长时间等待；未发现匹配上涨时不会擅自写入记录，并提供再次检测和手动记录入口。
- 到账结果使用数据库代次与原子领取防止重复记账、旧请求覆盖或重复弹窗；通知权限关闭时会在下次进入房间补显，页面重建前未确认的提示也会退回待展示状态。
- 版本升级为 `0.19.0`、Android `versionCode` 28，并作为强制更新版本发布。

### 开发者后台统计口径

- “累计实际使用设备”只统计至少成功发送过一次 App 启动心跳的手机；下载或下载请求不会写入用户表。
- “日活”按中国标准时间自然日和匿名设备摘要去重，代表当日实际打开 App 的设备数；同一手机当天重复打开仍只计 1。
- “最新版已使用”按设备最近一次启动心跳携带的 versionCode 统计，不以下载安装完成作为依据。
- “最新版独立下载”按匿名设备摘要去重；旧版本没有请求头时，只能使用不落库的网络特征 HMAC 近似估算。
- “下载请求”可能包含同一设备重新下载或系统重试，因此可能高于独立下载数，两者都不属于用户指标。

后台服务代码位于 [`server/server.py`](server/server.py)，通用 systemd 单元位于
[`server/elec.service`](server/elec.service)，Nginx 示例位于

### 配置更新服务

1. 将 [`update-manifest.example.json`](update-manifest.example.json) 复制到稳定的 HTTPS 静态地址。
2. 在已被 Git 忽略的 `local.properties` 中填写 `UPDATE_MANIFEST_URL`，然后重新构建 App。
3. 每次发布时上传正式 APK，执行 `shasum -a 256 文件名.apk`，把结果写入 JSON 的 `sha256`。
4. `forceUpdate: true` 表示所有旧版本必须升级；设为 `false` 时用户可以稍后处理或跳过该版本。
5. `minSupportedVersionCode` 大于用户当前 versionCode 时，即使 `forceUpdate` 为 false，该用户仍必须升级。
6. 发布 JSON 时应最后更新清单文件，避免用户先读到新版本信息却下载到尚未上传完成的 APK。

生产域名、服务器目录和正式清单不属于源码，仓库只提供
[`update-manifest.example.json`](update-manifest.example.json) 与通用部署模板。建议让
Nginx 直接托管更新清单和 APK，并让后台服务只监听环回地址。即使后台进程停机，App 的
查电费、提醒、本地历史和已有配置仍可使用。

## 0.4.0 修改内容

重复提醒现在会真正发起新的联网查询，完整流程为：

```text
每日查询低于提醒阈值
  ↓ 立即通知
按设定分钟数预约重复查询
  ↓
重新查询当前余额
  ├─ 低于恢复阈值：再次通知，并保留下一次重复查询
  └─ 达到恢复阈值：解除告警并取消重复闹钟
```

- 保存并启用新配置时，会同时清除告警状态并取消旧的重复闹钟。

- 内置 JID 失效时会终止重复查询，避免按分钟持续请求无效接口。
- App 启动着的低余额循环在手机重启、应用升级或时区变化后会自动恢复。
- 缴费后可点击“立即查询”提前确认恢复并取消循环，无需等待下一次闹钟。

## 首次使用

1. 点击“选择楼栋、楼层和房间”完成三级选择；接口异常时可展开高级入口手动填写 15 位房间码。
2. 填写提醒阈值、恢复阈值、重复提醒间隔（分钟）和每日时间，例如 `12:31`。
3. 点击“立即查询”，确认能显示剩余电量和金额。
4. 点击“保存并启用每日监测”。
5. 首次使用时按弹窗进入“后台提醒设置”，逐项完成通知权限、精确闹钟和电池优化设置。

## 调度原理

```text
保存 HH:mm
  ↓
AlarmManager 安排最近一次本地时间闹钟
  ↓ 到点，即使页面/进程不在前台
AlarmReceiver 先安排明天同一时间
  ↓
WorkManager 在联网条件满足后执行 ElectricityWorker
  ↓
查询余额 → 阈值判断 → 必要时发通知
```

Android 12+ 未授予精确闹钟权限时，应用仍会保留一个非精确计划，但系统可能延迟执行。网络断开时，任务会等待网络并按指数退避重试，因此通知时间也可能晚于设定时间。

## 本机配置与安全

公开仓库不会提供真实校付宝会话、更新地址或统计服务器地址。请在 Android Studio 自动
生成且已被 `.gitignore` 忽略的 `local.properties` 中加入：

```properties
XIAOFUBAO_SHIRO_JID=填写你有权使用的会话值
UPDATE_MANIFEST_URL=https://your-domain.example/update.json
ELEC_SERVICE_BASE_URL=https://your-domain.example
```

后两个地址可以留空，分别表示关闭自动更新和匿名统计。JID 即使通过私有配置注入，最终
仍会进入 APK，反编译 APK 可以提取它，因此只能使用你有权使用的会话；失效或泄露后应
立即替换。房间代码仍由 Android Keystore 加密保存在手机本地。

## 当前边界

- 支持多个房间；所有房间使用同一套固定校区和本机构建凭据，但配置、历史和提醒任务彼此隔离。
- 精确到分钟表示系统按该分钟触发，不保证网络请求和通知在 0 秒完成；断网和厂商省电策略会造成延迟。
- Android 深度休眠可能限制高频精确闹钟；设置 1 分钟适合短时测试，不建议作为长期正式间隔。
- 仅查询本人房间，不枚举房间，不自动充值，不接触支付密码。
